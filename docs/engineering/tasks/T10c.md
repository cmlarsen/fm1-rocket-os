# T10c: punch FX DSP core

Core lane for T10 in [build-plan.md](../build-plan.md#lanes-v3-2026-10-11). **New files only**; T10i wires the effects into X0X's master path, the FX key layer and the take later.

Read first: `CLAUDE.md`, the worker rules in `docs/engineering/build-plan.md`, `docs/product/interaction-model.md` (punch FX: six effects, tap latches, hold is momentary, HOME+FX resets), and X0X's master/FX code: `firmware/src/dsp/master.c`, `firmware/src/dsp/fxbus.*`, and how `engine.c` renders a block (sample format, block size, stereo or mono). The sample rate is 44,100 Hz (`FS` in `sequencer.h`).

**Ownership (new files only):** `firmware/src/dsp/perform.{c,h}`, `tests/host/perform_test.c`, `tests/golden/perform/`, and a `make unit-fx` target appended to the Makefile (keep the existing content).

## Effects
These run on the master stereo signal, after the mix and before the output stage:
1. **Repeat 1/8** and 2. **Repeat 1/16:** on engage, wait for the next 1/8 or 1/16 grid point of the transport (the caller passes the sample position of the next grid point), capture one slice, and loop it until release. Then hand back to the live signal at once, with a 2 ms crossfade at both ends so nothing clicks.
3. **Tape stop:** the playback rate falls to zero over about 0.6 s along a smooth curve, reading from the history buffer. On release, the live signal returns with a crossfade.
4. **Filter dive:** a resonant low-pass sweeps from open down to about 200 Hz over 1 beat, and holds there. On release it sweeps back over 1/4 beat.
5. **Echo throw:** sends the current signal into a tempo-synced 1/8-note feedback echo for as long as the effect is held. On release the echo tail keeps decaying naturally; it is not cut.
6. **Freeze:** captures about 120 ms and loops it with a 10 ms crossfade, a grain freeze, until release.

## Rules
- **Memory:** one shared history buffer of at most **32 KiB** for repeat, tape stop and freeze. Choose mono or stereo int16 and say which. Echo uses its own delay line, at most **16 KiB**. If a slice doesn't fit at slow tempos, use the longest that fits, document it, and test it.
- **Engagement:** only one buffer effect (1, 2, 3 or 6) is active at a time; a new one replaces the old with a crossfade. Filter dive and echo can stack with them.
- **API:**
  - `perform_engage(p, fx, latch)` and `perform_release(p, fx)`;
  - `perform_reset(p)`, for HOME+FX;
  - `perform_set_tempo(p, bpm_x10)`;
  - `perform_process(p, buf, nframes, next_grid_samples...)`, which runs in the ISR in constant time per sample, with no heap and no `double`.
  Engage and release come from the main loop through a small SPSC ring, like `core/seq/clip_engine.c`'s.
- Prefer fixed point. `float` is allowed, because X0X's master path uses it, but host output must stay bit-identical across runs (the build uses `-ffp-contract=off`).

## Tests (write first)
Write `tests/host/perform_test.c`. It feeds synthetic input (a sine plus clicks on the beat) and checks each effect:
- **repeat:** the output repeats the captured slice exactly, is sample-aligned to the grid, and has no step bigger than the crossfade allows at either boundary;
- **tape stop:** the output frequency falls monotonically and ends in silence;
- **filter dive:** the energy above 1 kHz drops by more than 20 dB;
- **echo:** taps fall at 1/8-note spacing and the tail decays after release;
- **freeze:** the output is periodic;
- **cleanup:** reset and release return the output to the input exactly, once the crossfade ends;
- **tempo:** at 60, 120 and 200 bpm.

Store waveform summaries, not hashes, as goldens. Build the tests also under `-fsanitize=address,undefined`. Compile the files for the device on deltron and report the code and RAM sizes.
