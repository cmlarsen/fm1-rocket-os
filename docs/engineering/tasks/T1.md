# T1: build X0X remotely and strip BREAK

The coordinator has already imported X0X 1.0.5 (`6cffa40`) with full history. `integration` is X0X with this project's docs merged on top. The `x0x` and `felucca` remotes exist. Your job is the rest of T1 in [build-plan.md](../build-plan.md).

Read first: `CLAUDE.md`, `BUILDING.md`, `README.md`, `LICENSING.md`, and the T1 row and worker rules in `docs/engineering/build-plan.md`.

## Facts
- Build host: `deltron.local` (ssh as `caleb`, key auth, x86-64 Ubuntu 26.04, passwordless sudo, docker). On Linux x86-64 the JieLi toolchain runs natively; no Docker needed.
- The Mac has Python in `.venv/` (mido, python-rtmidi, Pillow). Use `.venv/bin/python` for tools that need them.
- **Never flash hardware. Never run `tools/fm1_install.py` without `--info`.**

## Steps
1. **Toolchain on deltron.** Copy `tools/get_toolchain.sh` there and run it (installs to `~/.jieli/toolchain`). Clone the AC79 SDK to `~/fw-AC79_AIoT_SDK` on deltron as `BUILDING.md` says. Clone the reference sources that `tests/host/*` scripts look for (read the scripts for names and paths) next to the remote build tree.
2. **Top-level `Makefile`** with these targets. `FW_HOST ?= deltron.local`. Remote targets rsync the tree (excluding `.git`, `.venv`, `build/`) to `$(FW_HOST):~/fm1-build/<worktree-dir-name>/`, run there over ssh, and rsync `build/` artefacts back.
   - `make fw`: runs `./build.sh` remotely and brings back `build/x0x.fwsc`, `build/x0x.bin`, `build/loader/ota.bin`.
   - `make test`: runs `tests/run_tests.sh` remotely and returns its exit code; brings back `build/scenarios/`.
   - `make test-local`: runs `tests/run_tests.sh` on the Mac (whatever subset works there; document what doesn't).
   - `make check`: for now, `make fw` + the build's own checks (soft-double, size). T2 extends it.
   - `make help`: lists targets.
   Do not rename or move X0X's files or scripts; the Makefile wraps them.
3. **Reproduce the release.** `gh release download v1.0.5 --repo charlesvestal/fm1-x0x` (check the real tag name with `gh release list`). Compare it with what `make fw` produced from an untouched X0X tree: same bytes, or explain each difference (timestamps, version strings, paths) in the report. Do this **before** step 4.
4. **Record the loader.** Write the sha256 of the 1.0.5 `loader/ota.bin` (from the untouched build) to `tools/x0x_loader.sha256`, and add `tools/check_loader.sh <fwsc-or-build-dir>` that exits 0 only if the build's loader matches. The coordinator's unattended-flashing rule depends on this, so test it on a deliberately changed copy.
5. **Strip BREAK.** The BREAK generator and break bank are used "with the author's permission" from an unlicensed repo, so remove them entirely: `firmware/src/dsp/breaks.*`, `tools/*break*`, `tools/upload_breaks.py`, `tests/host/*breaks*`, `web/*breaks*`, `docs/img/screen-break.png`, plus every reference in the engine, sequencer, pattern struct, UI, storage, WASM build, tests and docs. If removing the `brk` field from `pattern_t` changes the storage format, keep a reserved field of the same size instead and say so. Remove `.github/FUNDING.yml` (it is the upstream author's).
6. **Licensing.** Update `LICENSING.md` to drop BREAK. Add a `LICENSES/` folder with the texts the tree needs (GPL-3.0 is `LICENSE`; add any others LICENSING.md names). Add a short section at the top of `README.md` naming this project (fm1-rocket-os, work in progress, see `docs/README.md`) and crediting X0X (Charles Vestal) and Felucca (Leo Kuroshita / Hügelton Instruments). Keep the rest of X0X's README below it.
7. **Verify after stripping.** `make test` passes (all suites except removed BREAK ones). `make fw` builds. `nm`/`strings` on `build/x0x.bin` show no `break`/`brk` generator symbols. WASM parity test (see `web/` and `tests/`) passes, run on the Mac if Node is available. `tools/check_loader.sh build` still passes (stripping must not change the loader).
8. **Stretch, max 45 minutes:** `make emu-binary` that builds simonjohansson/fm1-emulator on deltron and boots `build/x0x.fwsc` headless, saving a screenshot to `build/emu/home.png`. If it doesn't work in 45 minutes, stop, leave notes in the report, and don't commit half-working code.
