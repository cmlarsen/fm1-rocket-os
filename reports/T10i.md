# T10i: punch FX in LIVE

Integration lane for T10 ([build-plan.md](../docs/engineering/build-plan.md#lanes-v3-2026-10-11)), in parallel
with T7b. Wires [T10c](T10c.md)'s punch FX into the LIVE path: the master signal, the FX key layer, role
mutes and the debug stress. Nothing was flashed; the coordinator measures stress 3 on the device.

- Branch `cmlarsen/t10i-lane`, from `integration`. New tests, scenarios, goldens and this report.
- `make unit-core scenarios screens-lint parity check fw-debug` and `tools/check_loader.sh` on both
  packages all pass (see below).

## Build

### 1. Audio: `perform_process` on the master signal

`engine.c` places `perform_t` (**33,060 B**) in the shared `.pool` and calls, in `engine_render()`:

```c
perform_set_tempo(&perf, live_bridge_bpm_x10());
perform_process(&perf, out_l, out_r, n, perf_g8, perf_g16);   /* after fxbus_process_st, before master_process_st */
```

- It runs on the master stereo signal after the mix (`render_sub` ends in `fxbus_process_st`) and before
  `master_process_st`, on core 0, every block, in every view while the clip engine owns the audio
  (`live_bridge_active()`, which T7a makes true from power-on except in Classic).
- **Grid.** The next 1/8 and 1/16 distances come from `live_bridge_grid()` (new), which reads the clip
  engine's own step math (`step_sample + m*step_L + (step_frac + m*step_f)/bpm_x10`; the 1/8 grid is the
  next even step, so a swung odd step never moves one). `engine_render` takes them at the block's first
  frame, before the clip engine advances, so a repeat captures its slice on the exact grid sample. A
  stopped transport passes `PERFORM_NO_GRID`.
- **Engage/release/reset** come from the main loop through `perform`'s ring (`engine_perform_engage/
  release/reset()`); the UI calls them. The tempo is coalesced each block.
- **Echo throw.** `engine_perform_tick()` runs each UI frame. It keeps `perform`'s echo base in step with
  the project's delay settings (`proj.sound`'s `T_FX FX_DL_FDBK/TIME`) and, when `perform_echo_targets()`
  reports a real change, drives X0X's fxbus delay: `T_MIX MX_DLY = send` on every part, `T_FX FX_DL_FDBK`
  and `T_FX FX_DL_TIME`. On release it restores each part's own send and the project's fdbk/time. The
  initial `on=0` target is ignored (it is not a change), so boot leaves the project's sends untouched.

### 2. The FX layer in LIVE (`ui_live.c`)

- **FX held or double-tapped** opens the FX layer. While it shows, the first six lower keys are the six
  punches (`PERF_REPEAT_8, REPEAT_16, TAPE, FILTER, ECHO, FREEZE`); **tap latches, hold is momentary**.
  The upper keys 16-20 toggle the five role mutes. HOME+FX calls `perform_reset` (every effect off).
- **Releasing FX** returns to the layer underneath; latched effects stay on (they live in `perform`).
  A momentary effect still held ends when the layer closes.
- **The screen** is the LIVE 6 design: the header badge reads `FX`, the six cells are drawn in the two
  main bands with their `OFF / HOLD / LATCH` state, and the K1-K4 performance strip is the shared knob
  row. **The key LEDs** show the active effects (bright = latched or held, dim = available) and the muted
  roles (bright = muted) on the upper keys.

### 3. Mutes go through the clip engine

`core/seq/clip_engine.c` gains `CLIP_CMD_MUTE` (through its existing SPSC ring, ISR-safe), `muted[NROLES]`,
`clip_engine_mute()` / `clip_engine_muted()` and `clip_engine_mute_clear()`. Muting **releases the role's
sounding notes immediately** (note-offs at the window start) and **suppresses new note-ons**; the transport
and the role's position keep running, so unmuting rejoins the clip in time. `song->role[].muted` is kept
current (not the save state; a live mute does not mark the song dirty). `live_bridge.c` exposes
`live_bridge_mute()` / `live_bridge_muted()` / `live_bridge_mute_all()`.

### 4. Leaving LIVE

`live_leave()` releases every held note, resets every effect (`engine_perform_reset`), clears every mute
(`live_bridge_mute_all(0)`, a synchronous clear at the handoff because the clip engine stops rendering in
the Classic path) and closes the FX layer. `live_enter()` starts from the same clean state.

### 5. CPU: `rc_debug` stress 3

Stress 3 is stress 2 plus all six punches: after entering LIVE it engages each effect in turn (a few
blocks each, through `rc_settle`), leaving the three that stack (freeze + filter dive + echo throw) running
for the measurement. `rc_stop()` resets the effects. The coordinator measures it on the device; the host
profile is below.

## Memory

`perform_t` is 33,060 B (32 KiB of shared history + ~292 B of control) in the `.pool`. The echo has no
line of its own. `architecture.md`'s RAM table is updated:

| Build | Pool | `.data+.bss` |
|---|---:|---:|
| release (`make fw`) | **325,196 B of 344,064** | 95,888 B of 98,304 |
| debug (`make fw-debug`) | **326,988 B of 344,064** | 96,000 B of 98,304 |

Both keep the 8 KiB pool spare. The debug stress buffer `rc_pat` was cut from 32 patterns to **one**
(`live_bridge_map_n()` maps a single pattern), freeing ~16 KiB of debug pool the FX would otherwise have
spent.

## Host profile for `perform`

Measured on the Mac (`cc -O2 -ffp-contract=off`, ~4 GHz core), 256-frame blocks, 10.2 M samples:

| State | ns/sample | % of 44.1 kHz realtime (one core) |
|---|---:|---:|
| idle (pass-through) | 1.72 | 0.008 % |
| freeze + filter dive + echo throw | 7.39 | 0.033 % |

The device numbers come from the coordinator's stress-3 run (FG0 progress bucket is not affected: no new
`ENG_PROF_N` bucket is added, so the ED_STATS layout is unchanged).
