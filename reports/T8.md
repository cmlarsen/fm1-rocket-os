# T8: songs list, CRUD and the wired view (T8i)

T8 shipped the songs view and its templates in new files; T8i (this round) merged
`integration` (T7a), wired the view into `ui.c`, implemented the store side over
`song_io`, and moved the scenarios into the running suite with goldens. Nothing was
flashed.

## The store side (`song_io.c`)

A clearly separate **T8i block** at the end of `song_io.c` (so a parallel T7b change to
the clip API merges cleanly) implements the seam over `song_store` / `undo_stack`:

```c
void song_io_songs_list(void *ctx, int slot, song_row_t *out);
int  song_io_songs_current_slot(void *ctx);   /* cur_slot, or -1 (the project seed) */
int  song_io_songs_open(void *ctx, int slot); /* load + reload the clip engine */
int  song_io_songs_create(void *ctx, int kind, uint16_t bpm_x10, int key);  /* 0 Empty, 1 Starter */
int  song_io_songs_copy(void *ctx, int src);
int  song_io_songs_rename(void *ctx, int slot, const char *name);
int  song_io_songs_delete(void *ctx, int slot);
int  song_io_songs_undelete(void *ctx);
int  song_io_songs_first_free(void *ctx);
int  song_io_songs_can_undelete(void *ctx);
int  song_io_songs_clip_count(void *ctx, int slot);
const songs_ops_t *song_io_songs_ops(void);
```

`first_free` is the store's own policy: a slot that has never held a song first, then a
deleted one. `can_undelete` reads the top undo entry and the store's `deleted` flag, so a
delete whose slot was reused reports "can't undo". `cur_slot` is the slot the current
song lives in, or -1 while the song is still the boot project mapping; `song_io_save`
writes to `cur_slot` (or the first free slot for the seed), so the T6i semantics hold and
5 songs fit.

## The `ui.c` hook

- `V_SONGS` joins the view enum; `ui_songs_up()` is the runner's probe.
- **SAVE held ~600 ms opens SONGS** (`songs_save_tick`, mirroring PLAY's hold). A short
  SAVE tap still saves (the release-time `button_tap(B_SAVE)`), and SAVE used as a
  modifier (SAVE+REC/OCT/knob) is not a hold. It opens only outside LIVE and Classic.
- While `V_SONGS`, `input()` builds a `name_event_t` and calls `ui_songs_input()`,
  handles its `SONG_ACTION_*`, and keeps `ui.c`'s button bookkeeping in step (a press
  stamps `down_t`; the view owns the buttons, so their releases do not leak into the view
  underneath — a stale SEL hold once cleared the cursor clip on the way back).
- `ui_frame` draws the songs screen instead of header/main/knobs; `leds()` lights SAVE
  and leaves the keys dark.
- `songs_close` returns to the song home (`V_STUDIO`, `studio_enter`).
- The ops table is built in `ui.c` (`SONGS_OPS`), because **opening a song needs the
  engine**, which `song_io.c` cannot reach: `songs_op_open` stops the clip transport,
  releases every held note (`note_release_all`, T7a's table), calls `engine_all_off()`,
  flushes a stored current song, loads the chosen one and re-syncs the tempo.
  `songs_op_delete` deletes, and when it was the current song opens another (or a new
  Empty via `song_io_songs_create` when none is left).
- **The current song persists across a reboot**: opening stores the slot in the project's
  reserved byte (`proj.set.rsv[0]`) and marks the project dirty; the autosave writes it.
  `song_io_boot` now takes that byte as its preferred slot (then slot 0, then the
  project), so reopening a song and rebooting brings the same song back. The old
  reserved byte was zero, so a pre-T8i project still boots on slot 0.

goldens were regenerated — **only** the `songs` key changed (verified file by file); no
PNG golden moved.

## Notes

- **`copy` naming.** The store names a copy `<name> 2` (truncated, dropping `has_take`,
  since a take does not follow a copied song record). The menu shows "AS A COPY".
- **`ui_name.h`'s `NAME_MAX`** redefinition warning on the host (libc's `limits.h`): the
  view needs `SONG_NAME_LEN - 1`; T8c's header predates the include. Left as is (the
  device build does not define `NAME_MAX` and does not warn).
- **`songs_seam.h`** exists because `song_io.c` has `model.h` and `ui.c` has X0X's own
  `song_t`, so neither can include the other's header; the seam names no model type.
