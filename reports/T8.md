# T8: songs list and CRUD

Integration lane for T8, run in parallel with T7a. T7a owns `ui.c`, `song_io.*` and
`live_bridge.*`, so T8 shipped **new files only** and did not touch them: the songs
view, its templates, the host tests and the pending scenarios. Nothing was flashed.

This is the follow-up round that applies the Opus review
([`T8-review.md`](T8-review.md)); the review fixes are listed below. `integration` was
merged first, so `song_t` now carries `key` (0–11) and `scale` (`SCALE_*`) in the
former `rsv[2]`, validated on load.

Files (all new, except the additions to `Makefile`, `docs/open-questions.md` and this
report):

- `firmware/src/app/song_templates.{c,h}` — the Empty and Starter songs (STUDIO 8).
- `firmware/src/app/ui_songs.{c,h}` — the SONGS view (STUDIO 7, 8, 11, 12, 13).

## Review fixes

1. **Storage meter.** The bar and `N of 5` sit on one row, with no label
   (`sr_meter`): the bar runs 8…184 at y 160 and the count is right-aligned on the
   same row.
2. **`song_t.key` / `song_t.scale`.** Both templates set them, and the New-song K2
   drives them (`song_tmpl_key_scale`). An A-minor Starter stores `key == 9`,
   `scale == SCALE_MINOR` — checked in `song_templates_test.c`.
3. **The Starter is musical.** The chord clips are four bars, one chord per bar, on
   real progressions — I–V–vi–IV and vi–IV–I–V in major, i–VI–III–VII and VI–VII–i–VII
   in minor — with the second clip in a different voicing (a second inversion). The
   drums carry the accent row (downbeats and snares) and ghost hats on the off-beats,
   and the fill's crash is on step 0, so it marks the downbeat when the fill launches.
   Still deterministic; `test_chords` checks the roots follow the progression for all
   24 keys.
4. **Copy current with no current song.** The card is dimmed (a bordered, hollow card)
   and SEL does nothing — no `5 SONGS MAX`. `test_copy_no_current` checks the inert
   behaviour and the render is `new_copy_nocurrent.png`.
5. **The delete ring.** A 5 px stroke (five concentric circles), the rows behind the
   dialog are blanked so no fragments stick out at the right edge, and the footer reads
   `RELEASE keep · HOME+REC undo`.
6. **Delete is one gesture.** There is no separate confirm screen. On the menu's
   Delete row, holding SEL fills the ring for 1.5 s and deletes; releasing early keeps
   the song. The ring is a dialog drawn over the menu (`sr_delete`).
7. **Return codes.** `DELETED` and `RENAMED` appear only when the op returns 0; on
   failure the view shows `SAVE FAILED` and leaves the state (the rename editor stays
   open, the menu stays up). `open`, `create_from` and `copy` map their failures the
   same way.
8. **Slot choice and undo.** `songs_ops_t` gained **`first_free`** (the slot the next
   create/copy would use: a never-used slot first, then a deleted one, or `-2`) and
   **`can_undelete`** (1 while the most recent delete can still be undone). The view
   shows `5 SONGS MAX` from `first_free` before it builds a song; reusing a deleted
   slot seals its undo, and the HOME+REC path then reports `CANNOT UNDO`.
   `test_slot_policy` walks the whole sequence with the fake.
9. **Empty slots and `+ New song`.** An empty slot shows `empty` once (in the name
   column, no meta), and the `+ New song` row gets the design's dashed border.

## The seam T8i binds to `song_io` (exact signatures)

`ui_songs.c` never reads flash or the engine. It talks to the songs through one ops
table, so it is testable against a RAM fake and the integration can bind it to the
store. This is the surface `song_io` must expose (or that T8i adapts to it) — from
`firmware/src/app/ui_songs.h`:

```c
typedef struct {
    char    name[SONGS_NAME];   /* 12: SONG_NAME_LEN; -1 NUL */
    uint8_t used;               /* a live (undeleted) song exists */
    uint8_t has_take;
    uint8_t current;
} song_row_t;

typedef struct {
    void *ctx;
    void  (*list)(void *ctx, int slot, song_row_t *out);  /* slot 0..SONGS_SLOTS-1; deleted reads free */
    int   (*current_slot)(void *ctx);                     /* the edited song, or -1 */
    int   (*open)(void *ctx, int slot);                   /* stop, flush if dirty, load, reload; 0 = ok */
    int   (*create_from)(void *ctx, const void *song);    /* const song_t *; first free slot, or -2 */
    int   (*copy)(void *ctx, int src);                    /* first free slot, or -2 */
    int   (*rename)(void *ctx, int slot, const char *name);
    int   (*del)(void *ctx, int slot);                    /* durable delete + undo entry */
    int   (*undelete)(void *ctx);                         /* UNDO_DONE / UNDO_EMPTY / UNDO_CANNOT */
    int   (*first_free)(void *ctx);                       /* never-used first, then deleted; -2 full */
    int   (*can_undelete)(void *ctx);                     /* 1 while the last delete is undoable */
    int   (*clip_count)(void *ctx, int slot);             /* menu + delete ring; -1 = unknown */
} songs_ops_t;
```

Semantics the fake in `tests/host/ui_songs_test.c` pins down, and that the real ops
must match:

- `list` reports a deleted slot as `used = 0` with an empty name (the store's own
  rule), so the delete is reflected before the undo.
- `open` is the "the song on screen is the song" path: stop the transport, flush the
  current song if dirty (the autosave safety rules), load `slot`, reload the clip
  engine.
- `first_free` is the "first free slot" policy: a slot that has never held a song
  first, then a deleted one; `-2` when all `SONGS_SLOTS` are taken. `create_from` and
  `copy` use it and return the slot they wrote (or `-2`).
- `del` uses the store's durable delete and, when the deleted song was current, opens
  another (or a new Empty when none is left), per T8 step 5.
- `undelete` is one level (`undo_stack`'s `UNDO_DELETE_SONG` path); once a deleted
  slot is reused its sequence check returns `UNDO_CANNOT`, which `can_undelete`
  surfaces to the view.

The template signatures (both now take the New-song key):

```c
void song_template_empty(song_t *out, uint16_t bpm_x10, int key);     /* key 0..23 */
void song_template_starter(song_t *out, uint16_t bpm_x10, int key);
uint8_t song_tmpl_key_scale(int key);   /* SCALE_MAJOR / SCALE_MINOR */
```

`ui_songs.c` is include-style (it draws through gfx.c's statics), so `ui.c` includes it
after `gfx.c` and `ui_name.c`. Everything the shell calls:

```c
void        ui_songs_begin(songs_ui_t *u, const songs_ops_t *ops);
void        ui_songs_end(songs_ui_t *u);
int         ui_songs_active(const songs_ui_t *u);
void        ui_songs_refresh(songs_ui_t *u);
int         ui_songs_input(songs_ui_t *u, const song_event_t *ev);   /* SONG_ACTION_* */
void        ui_songs_draw(const songs_ui_t *u, uint32_t ms);
void        ui_songs_leds(const songs_ui_t *u, uint32_t *btn, uint32_t *key, uint32_t *dim);
const char *ui_songs_toast(const songs_ui_t *u);
```

## What T8i needs in `ui.c` (the one hook, expanded)

The coordinator's T8 block calls for the `ui.c` hook. Concretely, once `ui_songs.c` is
included after `ui_name.c`:

1. **A view**: add `V_SONGS` to the view enum (and `VIEW_N`). `ui_songs_active()` is the
   test for "the songs view is up".
2. **Open it on a SAVE long-hold** (~600 ms, mirroring PLAY's hold in `live_play_tick`):
   on the hold, `ui_songs_begin(&songs, &ops)` and `set_view(V_SONGS)`. SAVE's existing
   short-press uses stay as they are.
3. **Input**: while `ui_songs_active()`, build a `name_event_t` from
   `plat_buttons() / plat_keys() / plat_enc(EN_*) / plat_ms()` and call
   `ui_songs_input()`; on `SONG_ACTION_CLOSE` / `SONG_ACTION_OPENED`,
   `ui_songs_end()` and `set_view(V_HOME)` (the song home). Route HOME+REC to the view
   (it handles the delete undo) before the global undo.
4. **Draw**: while active, `ui_songs_draw(&songs, plat_ms())` instead of
   `draw_header()` + `draw_main()` (the view draws its own header in two bands).
5. **Footer / LEDs**: `ui_songs_leds()` ORs in the SAVE LED; the footer is the view's own.
6. **`#undef NKEYS`**: `ui_songs.h` includes `plat.h` and its `.c` includes `model.h`,
   which both define `NKEYS` (T8c's heads-up). `ui_songs.c` already `#undef`s it around
   the `song_templates.h` include, so the include order in `ui.c` is: `gfx.c` →
   `ui_name.c` → `ui_songs.c`.

## Tests

- `make unit-songs` (added to `unit-core`), also under ASan/UBSan:
  - `song_templates_test` — Empty and Starter validate; the key and scale are stored
    (A minor → key 9, `SCALE_MINOR`); Starter has 4 drums, 3 bass, 3 lead, 2 chords and
    1 FX; the drum clips are 16 steps with accents and ghost hats and the chords are 64
    steps; the fill's crash is on step 0; the chord roots follow the progression for
    all 24 keys; the bass line opens on the key's root and its third follows
    major/minor; the tempo clamps to 20–300 BPM; a repeated call is byte-identical.
  - `ui_songs_test` — the list and its cursor, open, the New screen and both templates,
    Copy current with no current song (inert), the 5-slot limit and its toast, the
    menu, open/copy, rename (confirm and cancel), delete with the hold ring,
    release-early keep, HOME+REC undo, the `first_free`/`can_undelete` slot policy with
    a `CANNOT UNDO` after reuse, and a deterministic two-render check.
- `make unit-core`, `make scenarios`, `make screens-lint`, `make parity` pass on the
  Mac (parity: WASM matches native).
- `make check` builds on deltron.local and `tools/check_loader.sh build/x0x.fwsc`
  confirms the loader is X0X 1.0.5's.
- The new files are **not in the firmware yet** (T8i includes them), so `make fw` is a
  regression check. They are also compiled for the pi32v2 with the JieLi clang in a
  throwaway TU (`gfx.c + ui_name.c + ui_songs.c`, and `song_templates.c`).

## Pending / notes for the coordinator

- **Scenarios.** `tests/scenarios/pending/t8_songs.x0x`, `t8_edit.x0x` and
  `t8_delete.x0x` are the T8 scenarios (list + create + limit; menu + rename + copy;
  delete + undo + reboot, and open + reboot). They are deliberately outside
  `tests/scenarios/` so `make scenarios` skips them until T8i wires the view; see
  `tests/scenarios/pending/README.md` for the runner support and the goldens they
  expect (`s01_*`…`s13_*`). The delete scenario uses the single-gesture hold.
- **`copy` naming.** The view does not name a copy; the store op decides (the fake
  uses `<name> 2`). The menu shows "AS A COPY".
- The `song_io` side of the ops table is T8i's to implement; T8 kept `ui.c` and
  `song_io.*` untouched, so there is no merge conflict with T7a.
