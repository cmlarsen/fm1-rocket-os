Core lane for T5 ([build-plan.md](../docs/engineering/build-plan.md#lanes-v3-2026-10-11)). New files only;
the engines are not wired into X0X's engine, UI or project yet (that is T5i). Nothing was flashed.

## Bit-identical acceptance (the main test)

`tests/host/run_fm6.sh` and `run_noise.sh` fetch Felucca's **original** `fm6_core.c`, `dsp.c`, `eng_noise.c` and `gen_tables.py` from the `felucca` remote into `build/ref/` and compile them as a host reference. The port is compiled from `firmware/src/dsp`. Both are driven by the same note script and the output is compared with `memcmp`.

- **FM6: 168 comparisons bit-identical** — 8 factory patches × 7 notes (24..96) × 3 velocities (30/100/127), 64 CTL blocks each, through the core's own framing (LFO, amplitude ramp, DC blocker). This compares the ported `fm6_core.c` + tables against Felucca's.
- **NOISE: 32 comparisons bit-identical** — the 4 presets (WIND/RAIN/ARCADE/METAL) × 4 notes × 2 filter shapes, 512 samples each. This compares the ported DSP against Felucca's `eng_noise.c`.
- The reference tables are generated by **Felucca's own** `gen_tables.py`, the port's by `tools/gen_fm6_tables.py`; both were checked equal byte-for-byte, so the tables are covered too.

**Block size / sample format.** No conversion is needed at the DSP boundary: Felucca's FM6 core computes exactly `CTL` (32) samples and NOISE renders any length, so the port is byte-identical with no re-scaling. The adapter's *output* is a separate matter (below).

## Adapter API (what T5i wires)

`eng_fm6.h` — polyphonic, `ENG_FM6_VOICES` (default 6, overridable at compile time; the constant T5i tunes for CPU):

```c
void eng_fm6_init(void);
void eng_fm6_set_patch(const uint8_t *v155);      /* the 155-byte voice, as OWN */
const uint8_t *eng_fm6_patch(void);
int  eng_fm6_load_slot(int s);                    /* 0..7 factory F1..F8, 8 OWN, 9..40 bank B1..B32 */
int  eng_fm6_slot(void);
void eng_fm6_set_vbank(const fm6_vbank_t *b);     /* the B slots' bank (T5i fills it from storage) */
void eng_fm6_set_param(int i, int v);             /* i = ALG,FB,MLVL,MRAT,MEG,VMOD,DTUN,SLOT */
int  eng_fm6_param(int i);
void eng_fm6_param_range(int i, int *lo, int *hi);
void eng_fm6_note_on(int note, int vel);
void eng_fm6_note_off(int note);
void eng_fm6_all_off(void);
void eng_fm6_render(int32_t *out, uint32_t n);    /* adds n mono int32 samples */
int  eng_fm6_voices_active(void);
```

`eng_noise.h` — `ENG_NOISE_VOICES` (default 2), the same shape (`init`, `set_param`/`param`/`param_range` for MODE..CRSH, `set_env(atk,dec,sus,rel)` in ms, `note_on/off`, `all_off`, `render`, `voices_active`).

**Sample format.** Both render **mono int32, Q15 (32768 = 1.0)**, one voice peaking near `VOICE_FS` (24000) — Felucca's `voice.c` convention. T5i adds `out[i] / 32768.0f` to X0X's float part bus (or `out[i] * (out_scale / 32768)` for the int32 output). `render` is block-size agnostic: FM6 chunks by `CTL` internally and NOISE serves any `n` from a small tail buffer, so X0X's 256-frame `REND_FRAMES` works as is.

**Voice allocation.** Felucca's `voice_alloc` idea, trimmed to X0X: a free voice, else the one furthest through its release, else the oldest; deterministic scan, no heap. The adapter test presses more keys than voices and checks the cap and that released voices end.

**What T5i still has to do** (out of this lane's scope):
1. Wire `eng_fm6_render` / `eng_noise_render` into `engine.c`'s part render, at X0X's scale.
2. **SLOT / the voice bank's flash transfer.** `fm6_vbank.c` is the format and a RAM bank only; Felucca's flash sector (`0xE7000`), `FM6B_BEGIN/WRITE/END` and the pre-erase CRC belong with X0X's `storage.c`.
3. The EDIT macros → X0X's parameter descriptors and the UI (the ranges are in `eng_fm6_param_range`), and the SLOT knob's factory/bank/OWN cycling.
4. NOISE's per-track FLT/SHP/PIT routing (Felucca's `m->cutoff/shape/fine`), which this adapter fixes at neutral.
5. **CPU/voice tuning:** `ENG_FM6_VOICES`; the FM6 core is the T5 CPU risk. One FM6 voice is ~3.5 KB flash + ~244 B RAM.

## Device compile (deltron.local, JieLi pi32v2 clang)

Compiled individually with `-target pi32v2 -O2 -ffunction-sections -fno-builtin -Wall -Wno-unused-function -mcpu=r3 -mfprev1 -ffp-contract=off -Ifirmware/hal -Ifirmware/src -Ibuild/gen` (the `O2_UNITS` flags from `tools/build.py`). They are **not linked** yet. Sizes from `objdump -h`:

| File | .text | .rodata | .data | .bss | flash (.text+.rodata) | RAM (.data+.bss) |
|---|---:|---:|---:|---:|---:|---:|
| `fm6_core.o` | 3456 | 8176 | 0 | 256 | 11632 | 256 |
| `fm6_vbank.o` | 1246 | 40 | 0 | 0 | 1286 | 0 |
| `eng_fm6.o` | 2674 | 1174 | 0 | 2444 | 3848 | 2444 |
| `eng_noise.o` | 2904 | 1764 | 0 | 288 | 4668 | 288 |
| **total** | 10280 | 11154 | 0 | 2988 | **21434** | **2988** |

`.rodata` is dominated by the FM6 tables (`FM6_EXP2` is 1025 × u32 = 4 KB, plus SINE, PITCH_OCT, the LFO/detune tables). `.bss` in `eng_fm6.o` is the 6 voices (244 B each) + the macro/patch state; most of it can move to the `.pool` (the shared engine memory) when T5i wires it, as Felucca does. `fm6_core.o`'s 256 B `.bss` is `fm6_bus` (two 32-sample buses).

## `make unit-engines`

On the Mac (needs the `felucca` remote and `python3`):

```
make unit-engines
```

runs `tests/host/run_fm6.sh` then `run_noise.sh`: generate the tables/patches, fetch the Felucca originals into `build/ref/`, compile both, run. Result:

```
FM6 parity ok        (168 bit-identical comparisons; range, bank, round-trip checks)
FM6 engine ok        (11 checks: adapter matches Felucca's framing, polyphony/steal,
                      silence after release, no clip, SLOT F/OWN/B)
NOISE parity ok      (32 bit-identical comparisons; determinism, no clip, adapter release)
```
