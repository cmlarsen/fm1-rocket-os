# T11c: MIDI input core

Core lane for T11 ([build-plan.md](../docs/engineering/build-plan.md#lanes-v3-2026-10-11)). New files
only; T11i connects this to the TRS and USB inputs, the LIVE play layer and the clip engine.
`core/model/model.h` is frozen and unchanged. Nothing was flashed.

- Files: `core/midi/midi_in.h`, `core/midi/midi_in.c`, `tests/host/midi_in_test.c`, `Makefile`
  (`unit-midi`), this report.
- `make unit-midi` builds the test with `-Werror` and runs it, then rebuilds it under
  `-fsanitize=address,undefined` and runs it again. Both pass on the Mac.
- One `midi_in_t` is one stream. TRS and USB each get their own instance. Everything is integer
  math; no heap, no `double`, no 64-bit division, constant time per byte. The state is
  caller-allocated (172 B) and the module includes only `core/model/model.h`.

## API

`#include "core/midi/midi_in.h"`.

```c
typedef struct {                        /* taken from the song (midi_cfg_from_song) */
    uint8_t live_channel;   /* 1..16, 0 = omni  (song_t.live_channel) */
    uint8_t pc_launch;      /* nonzero: PC launches (song_t.pc_launch)  */
    uint8_t pc_quant;       /* Q_BAR / Q_BEAT / Q_END (song_t.quant_default here) */
    uint8_t cable;          /* USB cable index to accept (0 on the FM-1) */
} midi_cfg_t;

typedef struct {                        /* every field may be NULL */
    void *ctx;
    void (*note_on)(void *ctx, uint8_t note, uint8_t vel);   /* live channel, vel 1..127 */
    void (*note_off)(void *ctx, uint8_t note);
    void (*all_off)(void *ctx);                              /* CC 120 or CC 123 */
    void (*launch)(void *ctx, uint8_t clip, uint8_t quant);  /* Program Change */
    void (*start)(void *ctx);   /* 0xFA */
    void (*cont)(void *ctx);    /* 0xFB */
    void (*stop)(void *ctx);    /* 0xFC */
    void (*spp)(void *ctx, uint16_t pos16);                  /* F2, 16th notes */
    void (*clock_lost)(void *ctx);
} midi_sink_t;

void midi_in_init(midi_in_t *m, const midi_cfg_t *cfg, const midi_sink_t *sink);
void midi_in_set_cfg(midi_in_t *m, const midi_cfg_t *cfg);   /* re-read after a song load */
void midi_in_set_fs(midi_in_t *m, uint32_t fs);              /* sample-counter rate */
void midi_in_byte(midi_in_t *m, uint8_t b, uint32_t sample);        /* TRS */
void midi_in_packet(midi_in_t *m, uint32_t pkt, uint32_t sample);   /* USB-MIDI packet */
void midi_in_tick(midi_in_t *m, uint32_t sample);            /* main loop: clock-lost check */
uint16_t midi_in_bpm_x10(const midi_in_t *m);               /* 0 until a tempo is known */
uint8_t  midi_in_clock_ok(const midi_in_t *m);              /* 0 after clock_lost */
void midi_cfg_from_song(midi_cfg_t *c, const song_t *s);    /* inline helper */
```

- Timestamps are the sample-counter value of the byte or packet; the caller passes them. `fs`
  defaults to 44100 (`MIDI_FS`, overridable or `midi_in_set_fs`), and only scales `bpm_x10`.
- `midi_in_packet` takes exactly what X0X's `plat_midi_in` returns and `usb.c` packs: low byte
  first, `byte0 = cable<<4 | CIN`, `byte1 = status`, `byte2 = d1`, `byte3 = d2`. It decodes the
  cable (packets on another cable are dropped) and the CIN (how many of the three bytes carry
  MIDI; SysEx CINs 4/5/6/7 map to 3/1/2/3).

## Behaviour

### Parser (one stream)

- **Running status.** A channel status (0x80..0xEF) is remembered; its data bytes keep arriving
  without a repeat. `Cx`/`Dx` want one data byte, every other channel message wants two.
- **Real-time (0xF8..0xFF)** is handled the moment it arrives and never touches the parser state,
  so it may fall inside another message or inside SysEx. F8/FA/FB/FC are ours; F9/FD/FE/FF are
  ignored.
- **SysEx** (0xF0) cancels running status and drops every non-real-time byte until 0xF7 or the
  next status byte (so a corrupted stream can still recover). A data byte with no running status
  is ignored.
- **Note On with velocity 0** is Note Off.
- System Common (F1/F2/F3) cancels running status and is collected for its data bytes; F2 is the
  Song Position Pointer, passed to `spp` as `d1 | (d2 << 7)` in 16th notes (its native unit).

### Routing (config from the song)

- Notes on the live channel (`live_channel`, 1..16; `0` = omni) reach `note_on`/`note_off`.
- **Program Change** on the live channel, when `pc_launch` is set, calls `launch(clip = program,
  pc_quant)`. Programs `0..NCLIPS-1` (0..26) launch; anything larger is ignored. With `pc_launch`
  clear, Program Change does nothing.
- **CC 120 and CC 123** call `all_off`, on the live channel (omni accepts any). At 0x7F/16 = 7
  and 123, and the channel filter keeps another channel's panic from stopping our notes.

### Clock follow

- **Tempo.** The window is one beat: the last 24 tick intervals. Their sum is the beat length and
  the estimate is a one-pole average in Q10 samples per beat,
  `est += (window - est) / 8`, turned into `bpm_x10 = 600*fs/beat`. A jitter-free beat is exact
  and the average removes the jitter. A window that jumps by more than `est/64` (1.56 %) is a real
  tempo change, so the filter snaps to it: a step is adopted **within one beat**, well clear of the
  jitter (at 200 bpm ±1 ms is 0.67 % of a one-beat window).
- **Transport.** FA/FB/FC call `start`/`cont`/`stop`.
- **Song Position Pointer** (F2) calls `spp`.
- **Clock lost.** `midi_in_tick(m, sample)` fires `clock_lost` once when ticks have been silent for
  more than one beat at the last tempo; ticks resuming clear it and it can fire again. A gap longer
  than a quarter second (`fs/4`) or a zero interval resyncs the tick window.

## `make unit-midi`

```
make unit-midi
```

builds `tests/host/midi_in_test.c` + `core/midi/midi_in.c` twice (plain `-Werror`, then
`-fsanitize=address,undefined`) and runs each. 15 cases, all passing:

| Case | Checks |
|---|---|
| running status | a channel status carries two messages; switching status |
| real-time inside | F8 inside a note message; FA/FB/FC interleaved |
| SysEx | swallowed between notes; cancels running status; real-time inside is delivered |
| velocity 0 | Note On vel 0 = Note Off |
| USB packets | CIN 9/8/12/15; another cable and a reserved CIN are dropped |
| channel filter / omni | channel 5 accepts, channel 6 is ignored; omni accepts all |
| PC launch | 0 and 26 launch, 27 and 127 are ignored, `pc_launch` off does nothing |
| CC 120/123 | both call `all_off`; another CC does not |
| SPP | two pointers, 256 and 16383 |
| transport | start, continue, stop in order |
| clock steady | 60/120/200 bpm with ±1 ms jitter: worst error **0.1 / 0.2 / 0.4 bpm** (±0.5 required) |
| clock step | 120→160 bpm settles within 24 ticks (1 beat) |
| clock ramp | 100→200 over 8 beats tracks up and settles within ±0.5 bpm |
| clock lost | fires past one beat (not at it), once only, again after ticks resume |
| fuzz | 1,000,000 random bytes and packets: no crash, and a fresh status byte recovers the parser |

The jitter and fuzz cases use a seeded PRNG, so the run is deterministic.

## Device build (deltron.local, JieLi clang 4.0.1, pi32v2)

Compiled the way `tools/build.py` compiles X0X's units (`-mcpu=r3 -mfprev1 -ffp-contract=off
-ffunction-sections -fno-builtin -I.`), `-Wall -Wextra -Werror` clean:

| opt | `.text` | `.rodata` | `.data` | `.bss` | flash | RAM | undefined syms |
|---|---:|---:|---:|---:|---:|---:|---|
| `-Os` | 862 B | 0 | 0 | 0 | **862 B** | **0 B** | `memcpy` |
| `-O2` | 864 B | 0 | 0 | 0 | **864 B** | **0 B** | `memcpy` |

All state is caller-allocated: `sizeof(midi_in_t)` is **172 B**. The one undefined symbol is
`memcpy`, already in the firmware (`firmware/src/libc.c`) for the init zero-fill. No globals, no
heap, no core-1 dependency.

## What T11i must wire

- Own one `midi_in_t` per stream (TRS, USB) in bss; `midi_in_init` with the config from the song.
  Point `midi_in_set_fs` at the sample counter's rate.
- **TRS:** call `midi_in_byte(m, byte, sample)` for each byte. X0X's `midi_uart.c` answers a whole
  message at once today, so this either replaces its packer or runs beside it fed from the same
  ring; one byte per call preserves running status and real time.
- **USB:** X0X already packs each packet as `cable<<4|CIN | status<<8 | d1<<16 | d2<<24` into
  `midi_in_q` (`usb.c`, `plat_midi_in`); call `midi_in_packet(m, pkt, sample)` for each. SysEx is
  filtered before the queue, so packets are channel voice + real time.
- **Notes:** `note_on`/`note_off` play the focused role. Hold the sounding notes (as `engine.c`
  keeps `bass_held`) so `all_off` and the note-off match release them, and so legato works.
- **Program Change:** `launch(clip, quant)` maps to `clip_engine_launch_quant(&eng, clip, quant)`.
- **Clock:** `bpm_x10` feeds `clip_engine_queue_bpm` when it changes (send only on a real change;
  the estimate is stable to ±0.1 so threshold it). `start`/`cont`/`stop` map to the transport,
  `spp` to a position seek, `clock_lost` to X0X's own external-clock timeout (it already falls back
  to internal after 0.5 s; this is the same signal at one beat).
- Call `midi_in_tick(m, sample_counter)` once per main-loop pass for the clock-lost check.
- Live SETUP rows "External keys channel" and "Program Change launch" write
  `song.live_channel`/`song.pc_launch`; re-run `midi_in_set_cfg` after a song loads or those rows
  change.

## Notes / decisions

- `spp` is in MIDI's own units (16th notes), so the callback can index the engine's `global_step`
  directly.
- CC 120/123 are channel-filtered with the live channel; a panic on a channel we do not own is not
  ours. Omni accepts any.
- `pc_quant` comes from the song's `quant_default` in `midi_cfg_from_song`; T11i can override it if
  a live SETUP row wants a different PC quantize.
- The parser is synchronous with no buffers: the caller's timestamp is the only clock, and a
  corrupt stream can only cost the bytes until the next status byte.
