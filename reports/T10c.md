# T10c: punch FX DSP core

Core lane for T10 ([build-plan.md](../docs/engineering/build-plan.md#lanes-v3-2026-10-11)). **New files
only**; the effects are not wired into X0X's master path, the FX key layer or the take yet (that is
T10i). Nothing was flashed. This revision applies [T10c-review.md](T10c-review.md) and the v1 RAM plan
in [architecture.md](../docs/engineering/architecture.md#ram-plan-v1-2026-10-11).

- **Sample rate:** `FS = 44,100 Hz` (`firmware/src/seq/sequencer.h`). `PERFORM_FS` defaults to it and can
  be overridden at compile time.
- **Built and tested on the Mac** (`make unit-fx`); **device-compiled on deltron.local** (see below).

## API (what T10i wires)

```c
enum { PERF_REPEAT_8, PERF_REPEAT_16, PERF_TAPE, PERF_FILTER, PERF_ECHO, PERF_FREEZE, PERF_NFX };

void perform_init(perform_t *p);
void perform_engage(perform_t *p, int fx, int latch);   /* latch 1 = tap, 0 = hold   */
void perform_release(perform_t *p, int fx);             /* never dropped             */
void perform_reset(perform_t *p);                       /* HOME + FX, never dropped  */
void perform_set_tempo(perform_t *p, uint16_t bpm_x10); /* coalesced to the latest   */
void perform_process(perform_t *p, float *l, float *r, uint32_t nframes,
                     uint32_t next_8, uint32_t next_16);
int  perform_latched(const perform_t *p, int fx);       /* for the LEDs             */

/* Echo throw drives X0X's fxbus delay; it has no line of its own. */
typedef struct { uint8_t send, fdbk, time, on; } perform_echo_t;
void perform_echo_throw(perform_t *p, int on);
void perform_echo_base(perform_t *p, uint8_t send, uint8_t fdbk, uint8_t time);
int  perform_echo_targets(perform_t *p, perform_echo_t *out);   /* 1 = changed */
```

- **Engage/release/reset come from the main loop through a small single-producer / single-consumer
  ring** (`PERFORM_CMD_RING = 16`), like `core/seq/clip_engine.c`'s. The audio ISR drains it at the
  start of `perform_process`; no locks, no heap.
  - **A release or a reset is never dropped.** When the ring is full they set a flag the ISR checks at
    the next drain; a reset also discards the stale queued commands. Engages may drop (best effort).
  - **The tempo is coalesced** to a single pending value, so a burst of tempo commands cannot fill the
    ring.
- **`perform_process`** runs on the master stereo signal, after the mix and before the output stage:
  `out = perform( mix ); master_process_st( out )`. It is in place on the two float arrays, like
  `fxbus_process_st` / `master_process_st`, up to X0X's 256-frame block. It is constant time per sample
  (no data-dependent loops, no `double`, no heap) and reset no longer clears a large buffer.
- **`next_8` / `next_16`** are the number of samples from the start of this block to the transport's
  next 1/8 and 1/16 grid points (`PERFORM_NO_GRID` when the transport is stopped). The caller
  recomputes them every block, so the engine never tracks the transport itself and never drifts: a
  repeat captures its slice on exactly the sample the caller calls the grid. (A block-relative
  countdown is what the ISR can use without a transport clock of its own - T10i derives it from the
  clip engine's step math.) A stopped transport has no grid, so a repeat engaged while stopped freezes
  the last period.

## Memory (the RAM plan)

One shared history buffer serves repeat, tape stop and freeze:

- `int16_t hist[16384]` - **mono int16, 32 KiB**. The master signal is summed to mono into it; the live
  passthrough stays stereo and a buffer effect collapses the image on purpose.
- **`sizeof(perform_t) = 33,060 bytes`** (32 KiB of history + ~292 of control state), which T10i places
  in X0X's shared `.pool`.
- **The echo has no line** (0 bytes): it drives X0X's fxbus delay (which the RAM plan cut to 1.0 s).

**Slow-tempo limits** for the shared history (a slice is capped at the longest that fits, and tested):

| Effect | length at `bpm_x10` | fits while | limit |
|---|---|---|---|
| repeat 1/8 | `13,230,000 / bpm_x10` | `<= 16384` | **>= 80.7 BPM** |
| repeat 1/16 | `6,615,000 / bpm_x10` | `<= 16384` | **>= 40.4 BPM** |
| freeze | 5,292 (fixed) | always | - |
| tape stop | lag grows to ~0.3 s (13,230 samples) | always | - |

Below the limits the slice is **capped at 16,384 samples** - grid-aligned at its start, no longer a
full grid period (tested at 60 BPM). The echo's time is X0X's: the controller asks for the 1/8 note and
`fxbus` shortens it to fit its own 1.0 s line, as it already does for the delay page.

## Effects

Run in this order per sample: **buffer effect (repeat / tape / freeze) -> filter dive**. The echo is
outside the audio path (it drives the fxbus delay).

1. **Repeat 1/8** / **2. Repeat 1/16.** On engage it waits for the caller's next 1/8 (resp. 1/16)
   grid point, captures the period that ends there from the history, and loops it exactly until
   release. A 2 ms crossfade at the engage and the release hand-off; the slice itself loops
   sample-exactly, so it repeats the captured slice bit for bit and is aligned to the grid.
2. **Tape stop.** Reads the history with a lag that grows as the playback rate falls linearly from 1
   to 0 over 0.6 s; the output is scaled by the rate so it ends in silence (the lag peaks at ~0.3 s,
   inside the 32 KiB history). On release the live signal returns over the 2 ms crossfade.
3. **Filter dive.** A resonant TPT state-variable low-pass sweeping from 16 kHz down to 200 Hz over one
   beat and holding; on release it sweeps back over 1/4 beat and then bypasses exactly. The cutoff is
   ramped control-rate (every 8 samples), **Q is ramped too** (0.707 -> 12), and the filter output is
   **blended in by the dive amount** so the engage, a re-engage mid-dive and the release cannot step.
   The state is **not reset** on engage: a re-engage continues from the current cutoff and amount.
4. **Echo throw.** Drives X0X's fxbus delay. While held it overrides the delay send, the feedback and
   the time to a synced 1/8 note; on release it restores the song's own values, so the delay's tail
   decays naturally. See `perform_echo_targets`.
5. **Freeze.** Captures the last ~120 ms (5,292 samples) and loops it with a 10 ms loop-wrap crossfade.
   After the first pass it wraps to `loop_pos = X`, so the crossfade region is not played a second time
   and the seam does not click; the loop is then periodic with period `L - X` (4,851 samples).

**Engagement.** Only one buffer effect (1/8, 1/16, tape, freeze) is active at a time; engaging a new
one keeps the old playing until the new one is ready (a repeat waits for its grid) and then crossfades
between them. Releasing or engaging over the outgoing effect of a replacement **fades it, never cuts
it**. Filter dive and echo stack on top of any of them. A latched tap on an already-latched effect
releases it; `latch = 0` is the momentary (hold) form. `perform_reset` clears everything at once.

**History under a loop.** The recording head keeps writing the live signal while a loop plays,
**skipping the loop's slice** (the only place its audio lives), so a later tape stop or repeat starts
from current audio rather than a stale snapshot. If a loop fills the whole buffer (the slow-tempo cap)
there is nowhere to write: the head stalls and a tape stop **plays the live signal** with the crossfade
instead of the stale snapshot. Both are tested (a freeze whose grain is 0.1 then a tape stop reading the
current 0.5; and the full-buffer fallback).

**Cleanup.** When nothing is engaged `a = 0` and the output is the input, sample for sample; the filter
bypasses exactly once its sweep back ends. The test asserts `memcmp` equality for release and reset.

## `make unit-fx`

```
make unit-fx
```

compiles `tests/host/perform_test.c` + `perform.c` twice (plain `-O2 -ffp-contract=off -Werror` and
`-fsanitize=address,undefined`, now also `-ffp-contract=off`) and runs both. Signals are generated with
`fastmath.h` (not libm), so the summaries are host-independent. The test feeds a synthetic transport
(integer 1/8 and 1/16 grids, like the clip engine) and checks:

- **cleanup:** idle output == input, sample for sample;
- **repeat:** exactness (period-to-period), grid alignment, and the **largest step at the engage and
  release boundaries** against the click-free input's own step + the 2 ms crossfade;
- **tape:** the pitch falls monotonically (204, 168, 126, 89, 52, 16 Hz) and ends in silence; engage
  and release boundary steps; the release is exact;
- **filter:** the 3 kHz energy drops 47 dB once held at 200 Hz (want < 20 dB); it holds; the **engage,
  re-engage (continues from the current amount) and release boundaries do not step**; the release is
  exact;
- **freeze:** after the first pass the loop is periodic with `L - X` and the **seam step stays within
  2x the input's step** (a click-free sine);
- **engagement:** a replacement with a bounded step; releasing the outgoing effect mid-replacement does
  not click; repeat + filter + echo stack, stay finite and reset exactly; a stopped transport freezes
  the last period;
- **history under a loop:** a freeze keeps recording, a tape after it reads the current audio (peak
  0.46, not the frozen 0.1), and the full-buffer fallback plays the live signal exactly;
- **echo controller:** the base/held/release targets, one-shot emission, and that the audio is
  untouched;
- **command ring:** 20 tempo commands coalesce to the latest, then a release leaves the effect off; a
  release overrides a full ring;
- **tempo:** 60/120/200 BPM (the 60 BPM slice is capped at 16,384).

`GOLDEN_UPDATE=1` rewrites the summaries in `tests/golden/perform/`. Result: `perform: ok` for both the
plain and the ASan/UBSan builds (no sanitizer findings).

## Device compile (deltron.local, JieLi pi32v2 clang)

Compiled with `build.sh`'s `O2_UNITS` flags
(`-target pi32v2 -O2 -ffunction-sections -fno-builtin -Wall -Wno-unused-function -mcpu=r3 -mfprev1
-ffp-contract=off`) and `objdump -h`:

| Object | `.text` | `.rodata` | `.data` | `.bss` |
|---|---:|---:|---:|---:|
| `perform.o` | **4,724** | 0 | 0 | 0 |

`.text` is `perform_process` (3,526) + `slot_wet` (316) + `release_fx` (220) + `perform_init` (324) +
the small entry points. There are no statics: all state is in the caller's `perform_t` (**33,060
bytes**), which T10i places in the shared `.pool`. The only undefined symbol is `memcpy` (the struct
copies in the slot swap), which `firmware/src/libc.c` provides. No `double`, no 64-bit division.

## What T10i must wire

1. **The master path.** Call `perform_process` on `out_l` / `out_r` after `fxbus_process_st` and
   before `master_process_st` in `engine.c:engine_render`, passing the next 1/8 and 1/16 grid
   distances from the clip engine's step math (`PERFORM_NO_GRID` while stopped).
2. **Place the state.** `perform_t` (~32.3 KiB) goes in `.pool`; `perform_init` at boot and
   `perform_set_tempo` when the song tempo changes.
3. **The echo throw.** Poll `perform_echo_targets` each UI tick and apply a change with
   `engine_set(T_MIX, part, MX_DLY, send)`, `engine_set(T_FX, 0, FX_DL_FDBK, fdbk)` and
   `engine_set(T_FX, 0, FX_DL_TIME, time)`; call `perform_echo_base` whenever the project's delay
   parameters change.
4. **The FX key layer.** FX held or double-tapped turns the first six lower keys into the six punches
   (tap latches, hold is momentary); `perform_engage(p, fx, latch)` / `perform_release(p, fx)`. Upper
   keys mute roles (not this module). HOME+FX calls `perform_reset`.
5. **The take.** Record the engage/release/reset events (T9's event log) so playback replays the same
   punches; the module has no hidden state to resync (a replay from a fresh `perform_init` is enough
   for reset).
6. **The LIVE SETUP rows and assigned keys** (T10i's own scope) can name `PERF_*`.

## Coverage of the review

1. Echo line removed; controller added; `sizeof(perform_t)` = 33,060 (target ~33 KB or less); history
   kept at 32 KiB.
2. Freeze wraps to `loop_pos = X`; seam-step test (<= 2x the input step) added.
3. Filter: no state reset, sweep from the current amount, Q ramped, blended by the dive amount;
   engage/re-engage/release step tests added.
4. The recording head keeps writing under a loop, skipping the loop's slice; the full-buffer fallback
   plays the live signal; both tested.
5. Releases and resets are never dropped (override flags); the tempo is coalesced; tested.
6. `reset_state` is constant time (no large buffer to clear).
7. Releasing the outgoing effect of a replacement fades it; tested.
8. Click-free sine inputs for the step and seam tests; the largest step is asserted at every engage,
   release and replace boundary.
9. `SAN_CFLAGS` gained `-ffp-contract=off`.
