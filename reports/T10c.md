# T10c: punch FX DSP core

Core lane for T10 ([build-plan.md](../docs/engineering/build-plan.md#lanes-v3-2026-10-11)). **New files
only**; the effects are not wired into X0X's master path, the FX key layer or the take yet (that is
T10i). Nothing was flashed.

- **Sample rate:** `FS = 44,100 Hz` (`firmware/src/seq/sequencer.h`). `PERFORM_FS` defaults to it and can
  be overridden at compile time.
- **Built and tested on the Mac** (`make unit-fx`); **device-compiled on deltron.local** with the JieLi
  pi32v2 clang (see below).

## API (what T10i wires)

```c
enum { PERF_REPEAT_8, PERF_REPEAT_16, PERF_TAPE, PERF_FILTER, PERF_ECHO, PERF_FREEZE, PERF_NFX };

void perform_init(perform_t *p);
void perform_engage(perform_t *p, int fx, int latch);   /* latch 1 = tap, 0 = hold   */
void perform_release(perform_t *p, int fx);
void perform_reset(perform_t *p);                       /* HOME + FX                */
void perform_set_tempo(perform_t *p, uint16_t bpm_x10);
void perform_process(perform_t *p, float *l, float *r, uint32_t nframes,
                     uint32_t next_8, uint32_t next_16);
int  perform_latched(const perform_t *p, int fx);       /* for the LEDs             */
```

- **Engage/release/reset/tempo come from the main loop through a small single-producer /
  single-consumer ring** (`PERFORM_CMD_RING = 16`), like `core/seq/clip_engine.c`'s. The audio ISR
  drains it at the start of `perform_process`; no locks, no heap. Dropping on a full ring is safe
  (a parameter flood, the UI still shows the state it sent).
- **`perform_process`** runs on the master stereo signal, after the mix and before the output stage:
  `out = perform( mix ); master_process_st( out )`. It is in place on the two float arrays, like
  `fxbus_process_st` / `master_process_st`, up to X0X's 256-frame block. It is constant time per
  sample (no data-dependent loops, no `double`, no heap). The one exception is `perform_reset`, which
  zeroes the 16 KiB echo line once, outside the per-sample path.
- **`next_8` / `next_16`** are the number of samples from the start of this block to the transport's
  next 1/8 and 1/16 grid points (`PERFORM_NO_GRID` when the transport is stopped). The caller
  recomputes them every block, so the engine never tracks the transport itself and never drifts: a
  repeat captures its slice on exactly the sample the caller calls the grid. (The spec said "the
  caller passes the sample position of the next grid point"; a block-relative countdown is what the
  ISR can use without a transport clock of its own - T10i derives it from the clip engine's step
  math.) A stopped transport has no grid, so a repeat engaged while stopped freezes the last period.

## Memory (the budget rule)

One shared history buffer serves repeat, tape stop and freeze:

- `int16_t hist[16384]` - **mono int16, 32 KiB** (16,384 samples). The master signal is summed to
  mono into it. **Chosen mono, not stereo:** it keeps a slice fitting at slow tempos (a stereo int16
  history would halve the frames and lose the 1/16 note below ~80 BPM). The live passthrough stays
  stereo; a buffer effect collapses the image on purpose, as a punch-in.
- `int16_t echo[8192]` - **mono int16, 16 KiB**, the echo's own line.
- The whole `perform_t` is **49,436 bytes** (hist 32,768 + echo 16,384 + ~284 of control state);
  T10i allocates it in X0X's shared `.pool`, like `dly_buf`.

**Slow-tempo limits** (a slice is capped at the longest that fits, and tested):

| Effect | length at `bpm_x10` | fits while | limit |
|---|---|---|---|
| repeat 1/8 | `13,230,000 / bpm_x10` | `<= 16384` | **>= 80.7 BPM** |
| repeat 1/16 | `6,615,000 / bpm_x10` | `<= 16384` | **>= 40.4 BPM** |
| freeze | 5,292 (fixed) | always | - |
| tape stop | lag grows to ~0.3 s (13,230 samples) | always | - |
| echo 1/8 | `13,230,000 / bpm_x10` | `<= 8191` | **>= 161.6 BPM** |

Below the repeat limits the slice is **capped at 16,384 samples** - still grid-aligned at its start,
no longer a full grid period. The test covers 60 BPM (capped) and 120/200 BPM. Below the echo limit
the delay **halves until it fits** (1/8 -> 1/16 -> 1/32), which stays on the beat: at 120 BPM it is a
1/16 (5,512 samples), at 60 BPM a 1/32. The test checks the 120 BPM halving. This is the honest
consequence of the 16 KiB cap; the musical 1/8 echo needs ~161 BPM or faster.

## Effects

Run in this order per sample: **buffer effect (repeat / tape / freeze) -> echo -> filter dive**.

1. **Repeat 1/8** / **2. Repeat 1/16.** On engage it waits for the caller's next 1/8 (resp. 1/16)
   grid point, captures the period that ends there from the history, and loops it exactly until
   release. A 2 ms crossfade at the engage and the release hand-off; the slice itself is looped
   sample-exactly (no wrap crossfade), so it repeats the captured slice bit for bit and is aligned to
   the grid.
2. **Tape stop.** Reads the history with a lag that grows as the playback rate falls linearly from 1
   to 0 over 0.6 s; the output is scaled by the rate so it ends in silence. The read lag peaks at
   ~0.3 s, well inside the 32 KiB history. On release the live signal returns over the 2 ms crossfade.
3. **Filter dive.** A resonant TPT state-variable low-pass (Q = 12, like `master.c`'s) sweeping from
   16 kHz down to 200 Hz over one beat, holding there; on release it sweeps back over 1/4 beat and then
   bypasses exactly. The cutoff is ramped control-rate (every 8 samples) and linearly in Hz, which the
   sanitizer build prefers: `fastmath.h`'s `fm_exp2f` shifts a negative int and trips UBSan.
4. **Echo throw.** Sends the current (post-buffer) signal into a tempo-synced feedback echo
   (feedback 0.5, return 0.7) while held. On release the send stops and **the tail decays naturally**;
   it is not cut. When the line goes quiet it idles.
5. **Freeze.** Captures the last ~120 ms (5,292 samples) and loops it with a 10 ms loop-wrap crossfade
   (a grain freeze); the 2 ms hand-offs are as above.

**Engagement.** Only one buffer effect (1/8, 1/16, tape, freeze) is active at a time; engaging a new
one keeps the old playing until the new one is ready (a repeat waits for its grid) and then crossfades
between them. Filter dive and echo stack on top of any of them. A latched tap on an already-latched
effect releases it; `latch = 0` is the momentary (hold) form. `perform_reset` clears everything at once
and returns the dry signal.

**Cleanup.** When nothing is engaged `a = 0` and the output is the input, sample for sample; the echo's
tail is flushed once it is silent; the filter bypasses exactly once its sweep back ends. The test
asserts `memcmp` equality for release, reset and the idle case.

## `make unit-fx`

```
make unit-fx
```

compiles `tests/host/perform_test.c` + `perform.c` twice (plain `-O2 -ffp-contract=off -Werror` and
`-fsanitize=address,undefined`) and runs both. Signals are generated with `fastmath.h` (not libm), so
the summaries are the same on any host. The test feeds a synthetic transport (integer 1/8 and 1/16
grids, like the clip engine) and checks:

- **cleanup:** idle output == input, sample for sample;
- **repeat:** exactness (period-to-period), grid alignment (the loop equals the input one slice back),
  and no step beyond `input + 2 ms` at the engage and release boundaries;
- **tape:** the pitch falls monotonically (204, 168, 126, 89, 52, 16 Hz over 0.6 s) and ends in
  silence; the release is exact;
- **filter:** the energy at 3 kHz drops 47 dB once held at 200 Hz (want < 20 dB); it holds; the release
  is exact;
- **echo:** taps at 1/8-note spacing (6,615 samples at 200 BPM) decaying 0.56, 0.28, 0.14, ... and
  still decaying after release; the 120 BPM halving;
- **freeze:** periodic with the 5,292-sample grain; consecutive grains identical; the release is exact;
- **engagement:** a new buffer effect replaces the old with a crossfade and no click; repeat + filter +
  echo stack, stay finite and reset exactly; a stopped transport freezes the last period;
- **tempo:** 60/120/200 BPM (the 60 BPM slice is capped at 16,384).

`GOLDEN_UPDATE=1` rewrites the summaries in `tests/golden/perform/`. Result: `perform: ok` for both the
plain and the ASan/UBSan builds (no sanitizer findings).

## Device compile (deltron.local, JieLi pi32v2 clang)

Compiled with `build.sh`'s `O2_UNITS` flags
(`-target pi32v2 -O2 -ffunction-sections -fno-builtin -Wall -Wno-unused-function -mcpu=r3 -mfprev1
-ffp-contract=off`) and `objdump -h`:

| Object | `.text` | `.rodata` | `.data` | `.bss` |
|---|---:|---:|---:|---:|
| `perform.o` | **3,154** | 0 | 0 | 0 |

`.text` is `perform_process` (2,358) + `slot_wet` (304) + `perform_init` (290) + the small entry
points. There are no statics: all state is in the caller's `perform_t` (**49,436 bytes**), which T10i
places in the shared `.pool`. The only undefined symbol is `memcpy` (the struct copies in the slot
swap), which `firmware/src/libc.c` provides. No `double`, no 64-bit division.

## What T10i must wire

1. **The master path.** Call `perform_process` on `out_l` / `out_r` after `fxbus_process_st` and
   before `master_process_st` in `engine.c:engine_render`, passing the next 1/8 and 1/16 grid
   distances from the clip engine's step math (`PERFORM_NO_GRID` while stopped).
2. **Place the state.** `perform_t` (~48.3 KiB) goes in `.pool`; `perform_init` at boot and
   `perform_set_tempo` when the song tempo changes.
3. **The FX key layer.** FX held or double-tapped turns the first six lower keys into the six punches
   (tap latches, hold is momentary); `perform_engage(p, fx, latch)` / `perform_release(p, fx)`. Upper
   keys mute roles (not this module). HOME+FX calls `perform_reset`.
4. **The take.** Record the engage/release/reset events (T9's event log) so playback replays the same
   punches; the module has no hidden state to resync (a replay from a fresh `perform_init` is enough
   for reset).
5. **The LIVE SETUP rows and assigned keys** (T10i's own scope) can name `PERF_*`.
